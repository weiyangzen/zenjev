# zenjev-rsi：让 schema、标签和模型一起自我改进的外层循环

**状态：研究方案（不是运行时实现）**
**更新：2026-11-26**
**权威说明：** `Docs/stage0_zenjev_blueprint.md` 是执行阶段的唯一权威。本文记录设计依据和建议，不改变 checklist 状态；采纳其中任何一项，都要按蓝图 §6 写迁移记录。配套：`jev_complete_plan.md`。

## 1. 它是什么

ZenJev 现有的 RSI 是 `zenjev-loop` 里的那一圈：摄入、自标注、训练 LoRA、发布代际、重部署。它改进的只有权重，schema 是固定的。

zenjev-rsi 在这一圈外面再加一层。数据里长出 schema 没有的概念时，让 schema 和标签也进入循环：发现新概念，把它闭合进 schema，重标，再交给内层去训练。内层不变。

| | 内层 RSI（已有）| 外层 zenjev-rsi（本文）|
|---|---|---|
| 改进的对象 | LoRA 权重 | schema、标签，以及由此产生的训练数据 |
| 节奏 | 按消费的记录数，持续进行 | 按数据批次或漂移告警，一轮一轮 |
| 出问题的信号 | F1 下降、loss 发散、输出非法 | 新概念被塞进旧标签；教师自己前后不一致 |
| 出问题时 | 崩溃判定加 reset | 开一轮 schema 评审，不重置权重 |

现在的缺口：schema digest 不匹配的记录进 quarantine，未知标签被拒绝或记为 `unmapped`。两条路都是把新东西挡在外面，没有把它变成 schema 一部分的流程。Stage 0.1 的"按语料校准 schema"是手工做的一次。

## 2. 原则

1. **学生和服务侧永远是闭集。** "开"只发生在教师一侧和监控一侧。
2. **标签归 schema 的所有者。** 循环产出证据和建议，取舍由所有者定，或由所有者明确授权的策略代行。
3. **先有判据再动手。** 判据和阈值在一轮开始前定好，中途不改。
4. **便宜的判据做内层，贵的做外层。** 只用教师就能量的先量，训练学生放在最后。
5. **每个 schema 版本由父版本加映射确定性生成。** 映射是唯一的权威。
6. **测试集不参与设计。**

## 3. 一轮怎么走

```
新数据 ─► 入口检查 ─► 抽样与留出 ─► 基线 ─► 开集发现 ─► 规约成候选概念
                                                          │
                                                   闭合决策（所有者或已授权的策略）
                                                          ▼
                 ┌──── 候选版本：只用教师的快判据 ◄─────────────┐
                 │ 通过                              不通过：改决策 │
                 ▼                                              │
           短程训练，看混淆 ── 有要改的 ──────────────────────────┘
                 │ 收敛或到上限
                 ▼
               冻结 ─► 重标与训练（交给内层 RSI）─► 晋升 ─► 监控
```

| 步 | 做什么 | 要点 |
|---|---|---|
| 入口检查 | 新数据先只解析、不标注 | 解析为空的记录必须有原因。不认识的格式不能被静默变成空输入 |
| 抽样与留出 | 固定比例、固定种子；留出集按组切分 | 同一组的记录不同时出现在训练和留出里。旧留出集的成员不动 |
| 基线 | 用当前 schema 让教师和学生各过一遍新数据 | 给同一条记录两份教师标签，量教师自己有多稳定。它是学生精度的参照上限 |
| 开集发现 | 教师标两遍：一遍不看分类树；一遍看分类树，但允许说"这是新概念" | 第一遍看新数据自己的结构，第二遍量现有 schema 装不下多少。在旧数据上跑一小份作对照 |
| 规约 | 原始标签先对到现有 schema，剩下的聚成候选概念 | 每个候选概念带上支持度，以及它的记录被归到了哪些现有标签 |
| 闭合决策 | 每个候选概念选一种处理方式 | 见下表 |
| 候选版本 | 生成候选 schema；先过只用教师的快判据，过了再做一次短程训练看混淆 | 只保留比已接受版本更好的候选。候选数、训练次数、教师时间都有上限 |
| 冻结 | 发布 schema 快照、映射、测试、决策记录 | 到上限仍未收敛，就停在已接受的最好版本。不为了收敛放宽阈值 |
| 重标与训练 | 新数据用新 schema 标注；旧数据审计后重标，或按映射换算 | 提示词变了，没改的字段也会跟着动。两种口径的标签不混用 |
| 晋升 | 新一代过门禁才替换旧的 | 旧分布上不能变差；各字段接近教师自己的一致率 |

闭合方式分两类：

| | 包括 | 对存量的影响 |
|---|---|---|
| 兼容 | 并入现有标签；补充现有标签的描述；新增标签；暂不建模，留在候选登记表里 | 旧标签的名字和含义基本不变 |
| 不兼容 | 拆分；合并、改名、换父类；删除 | 受影响的记录要重标，或按映射换算 |

两条防止走偏的规则：

- **不能靠合并刷一致率。** 所有标签合成一个，教师的一致率就是 100%。所以所有者要先给出"必须保留的区分"，这些区分不允许被合并。
- **小标签要单独量。** 占比很小的标签在通用验证集里只有几条，量不出东西。新增的标签要单独凑一批样本来看。

混淆怎么读：

| 读到什么 | 判读 |
|---|---|
| 某对标签教师自己前后不一致，学生也混淆 | 边界不清，是 schema 的问题 |
| 教师一致，学生混淆 | 学生没学会，不是 schema 的问题 |
| 新标签学不出来，错误都回到它原来所在的标签 | 这个区分在当前数据量下立不住 |

## 4. 落到 Jev 的现有机制上

| 现有机制 | 现状 | 建议的扩展 |
|---|---|---|
| Schema 合约（蓝图 §1.1）| 换 schema 版本就开新的 adapter 和数据 lineage，除非有被接受的迁移 | 写明"被接受的迁移"要什么：映射文件、stable 层的换算或重标、新的 canary、短程训练通过、迁移记录。兼容迁移在 LoRA 结构不变时可以沿用 warm start；不兼容迁移开新 lineage |
| replay buffer 三层 | recent、stable、canary | recent 对应新分布，stable 对应旧分布。每个 schema 版本一份 canary，旧 canary 按映射保留为回归集 |
| `DriftMonitor` | 只看模型侧信号，动作是 reset | 增加 schema 侧信号：`unmapped` 的占比、教师说"这是新概念"的比例、教师重复标注的不一致率。动作是一条 `schema_review` 事件，不是 reset。同样要求 `consecutive_windows` 个窗口连续成立 |
| quarantine | schema 不匹配的记录到此为止 | 作为开集发现的输入 |
| 教师不一致率 | 可选的晋升门禁之一 | 分两种看：集中在少数几对标签上的是 schema 边界问题，进 `schema_review`；普遍升高的是数据或教师的问题 |
| 代际账本 | 每一代记 `schema_digest` | 增加 `schema_migration_id`，账本上能看出哪一代跨了 schema |
| 晋升门禁 | 冻结 holdout、canary、最近窗口 | 增加两条：各字段不低于教师自己的一致率减容差；旧 canary 按映射换算后不显著变差 |
| 有限标签集与 allowlist | 未知标签拒绝 | 未知标签不直接进 allowlist，走"候选、试行、生效"的生命周期 |

**标签的生命周期：** 候选（在登记表里累积证据）、试行（进了某个候选版本）、生效（已发布）、弃用（保留为别名，映射指向继任）、移除。一轮里没闭合的概念不丢，留在登记表里等下一轮。

## 5. 自动化等级

| 等级 | 含义 | 所有者介入的点 |
|---|---|---|
| L0 | 手动 | 每一步 |
| L1 | 自动跑到"候选概念、证据、建议的处理方式"；判据和短程训练自动跑 | 每次闭合决策、冻结、晋升 |
| L2 | 策略授权的变更类别自动批准；门禁全过时自动冻结和晋升，所有者有否决窗口 | 越权的类别；否决 |
| L3 | 全部类别按策略和门禁执行 | 只有升级 |

- 授权按变更类别分别给，不是整条流水线一个开关。
- 一个类别能不能交给自动，看循环的建议与所有者的决定是否长期一致。其中一部分决定要在所有者没看到建议时做，否则一致率会被建议本身带高。
- 所有者推翻一次自动决定，该类别退回人工。
- 不兼容的类别和最高等级，只在所有者明确授予后才启用。
- 策略的每次改动留迁移记录，做法与蓝图 §6 相同。

## 6. 建议的检查项（提案）

以下是给蓝图的候选条目，没有编号，不改变任何现有状态。

- 入口检查：空记录必须有原因，带故障注入的回放测试。
- schema 侧漂移信号与 `schema_review` 事件，带合成漂移的回放测试。
- 开集两遍的教师调用和输出校验。
- 规约器与候选登记表。
- schema 生成器：父版本加映射生成快照和测试，重新生成历史版本时逐字节一致。
- 只用教师的快判据，以及短程训练的混淆判读。
- 迁移事务：映射文件、stable 层换算或重标、新 canary、账本里的 `schema_migration_id`。
- 策略文件与授权统计。

## 7. 风险

- **开集被现有标签牵引。** 两遍开集和旧数据对照用来对付它，但教师对新领域的命名仍然带着它自己的偏好。候选概念要经过所有者确认。
- **新标签的记录数够，但全来自一两个组。** 支持度要同时看组数。
- **频繁改 schema 的代价。** 每次不兼容变更都意味着重标和口径的断裂。
- **短程训练被当成精度结论。** 它只能读混淆的结构。
- **自动授权被少数决定带偏。** 一致率要有足够的样本，并且按类别统计。
- **教师换代。** 教师模型或它的服务配置变了，标签口径也会变。教师的版本和配置是标签身份的一部分。
